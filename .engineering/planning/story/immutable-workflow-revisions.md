# Immutable workflow revisions and draft authoring

## Outcome

An authenticated engineer can create a workflow draft, mutate its graph safely, publish a canonical immutable revision, and activate an owned revision.

## Context

The current 0.1.0 release contains only `WorkflowId`. This story replaces that placeholder with a definition-only Service SDK package whose semantic source is `spec/workflow/system.yaml`.

## Acceptance

- ESS declares `Workflow`, `WorkflowDraft`, `DraftNode`, `DraftEdge`, and immutable `WorkflowRevision` with explicit ownership relations.
- The closed semantic node algebra is `compute`, `read`, `call`, `judge`, `wait`, `invoke`, `emit`, and `complete`; semantic graph data contains no layout coordinates.
- Commands are `create_workflow`, `create_draft`, `discard_draft`, `validate_draft`, `publish_draft`, `activate_revision`, `add_node`, `replace_node`, `remove_node`, `connect_nodes`, and `disconnect_nodes`.
- Queries are `list_workflows`, `get_workflow`, `list_drafts`, `get_draft`, `list_revisions`, and `get_revision`, with deterministic pagination.
- Every mutation requires an idempotency key and expected stream version; replacing a node preserves its ID.
- Removing a referenced node is refused until edges are explicitly disconnected.
- Connecting missing, self, duplicate, or cyclic nodes is refused.
- Publishing refuses empty, dangling, cyclic, oversized, or invalid drafts and creates a canonical immutable revision and digest.
- Published revisions cannot be updated or deleted, and activation refuses a revision owned by another workflow.
- ESS validation, deterministic generation, generated-client/server parity, tenant isolation, and conformance tests pass.

## Out of Scope

Execution, triggers, schedules, leases, cancellation, revision deletion, layout persistence, and predecessor compatibility.

## Open Questions

None. Draft-then-publish and the closed node algebra were selected by the operator on 2026-09-03.

## Scope

- cited: `spec/workflow`, `service.yaml`, `service/runtime.yaml`, `service/scenarios`, `generated`, workspace manifests, README, changelog, and release metadata.
- inferred: all runtime behavior remains generated by Service SDK; Workflow contains no handwritten service or client adapters.
